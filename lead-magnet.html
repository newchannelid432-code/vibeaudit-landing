10 AI App Leaks You Probably Have Right Now

Most AI apps leak money in one of these 10 places. Each check takes under 2 minutes. If you hit a red flag, you know you need the full scan. No tools, no signup.

1. Key in the browser

Open DevTools → Network → reload your app → look for Authorization: Bearer sk-… or an API key in request headers/URL. Red flag: your key is visible to anyone who opens the page.

2. Key in client code

Open your JS bundle and search for sk-, api_key, OPENAI_API_KEY, Bearer. Red flag: a key is shipped to the browser at all.

3. Open /v1 endpoint

Hit your app's /v1/chat/completions (or similar) with no auth header. Red flag: it responds with a completion, not 401/403.

4. Relay with no origin check

Send a request from a random origin — curl -H "Origin: https://evil.example" …. Red flag: it responds, no CORS 403, no allowlist.

5. No rate limit

Fire 50 requests in 10 seconds. Red flag: all succeed. Your API budget is a faucet.

6. Exported keys in dotfiles

Check .env files, ~/.bashrc, ~/.zshrc, and dotfile repos. Red flag: a real key sits anywhere on disk unencrypted.

7. Key in git history

Search your repo history for sk-. Red flag: a key was committed even if "rotated" later — the old one still works until revoked.

8. Public IP with no auth

curl http://<your-server-ip>:8000/v1 from outside your network. Red flag: it responds. Anyone on the internet can use it.

9. Unguarded admin/panel

Check /admin, /panel, /_next, /api/debug. Red flag: they load without a login.

10. Client tokens with broad permissions

Check network calls for your Supabase/Firebase anon key exposed with read-write access on sensitive tables. Red flag: data tables are editable without auth.
